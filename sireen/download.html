Get SIREEN v0.1.1

Two ways to use SIREEN: the command-line interface for scripting and automation, or the VS Code extension for an integrated editing experience. Both use the same backend engine and produce identical results.

Tester release

SIREEN v0.1 is an early-stage release for independent security researchers. It does not replace a professional audit, discover all vulnerability classes, or guarantee security. Results marked needs_review require manual triage.

Option A: SIREEN CLI

Recommended

Run audits from the terminal. Best for scripting, CI pipelines, and batch analysis of multiple contracts or entire Foundry projects.

What it does

  • Accepts a single .sol file or a full Foundry project directory
  • Discovers functions, state variables, and external-call sites
  • Generates attack hypotheses (heuristic or AI-assisted)
  • Produces Foundry PoC test files for supported vectors
  • Compiles and executes PoCs with forge test (when Forge is available)
  • Persists audits in a local SQLite database
  • Exports Markdown and JSON reports with evidence IDs

Repository access required

The SIREEN source repository is not publicly readable today — https://github.com/0766243478/goalaif currently returns HTTP 404, so git clone will fail until access is granted. Request access from the project owner at github.com/0766243478, then run the commands below. Checked 2026-10-15.

Step 1 — Clone and install

git clone https://github.com/0766243478/goalaif.git
cd goalaif/gaolaif/backend
python -m pip install -r requirements.txt
python -m pip install -e .

This installs the sireen command into your Python environment. If Python's Scripts directory is on your PATH, you can use sireen directly. Otherwise, use python -m sireen_cli.

Step 2 — Configure your API key (optional)

SIREEN works fully offline without an API key. Adding one enables AI-assisted hypothesis generation, which can suggest additional attack angles beyond heuristic patterns.

cd goalaif/gaolaif/backend
cp .env.example .env.local

Edit .env.local and add your own OpenRouter key:

# In .env.local
OPENROUTER_API_KEY=sk-or-v1-YOUR-KEY-HERE
Security

.env.local is gitignored by default. Never commit real keys. Never share this file. If you suspect a leak, revoke the key on OpenRouter immediately and generate a new one.

Get a free key at openrouter.ai. Free-tier models are used by default.

Step 3 — Run your first analysis

sireen audit ./MyContract.sol --report

Audit a full Foundry project:

sireen audit ./my-foundry-project --project --json

Step 4 — View findings and evidence

sireen audit ./MyContract.sol --json            # Full JSON output
sireen audits                                   # List past audits
sireen show <audit-id>                          # Show one audit
sireen report <audit-id> --output report.md     # Export Markdown

Option B: SIREEN for VS Code

v0.1.4

Analyze Solidity code directly inside your editor. The extension connects to the local SIREEN backend and displays findings, evidence packs, and live audit progress.

Current status

Not published to the Visual Studio Marketplace

The extension is currently distributed as a .vsix file only. You must install it manually or build it from source. A Marketplace publication is planned for a future stable release. The extension has been built successfully but has not been runtime-tested in a live VS Code environment.

Step 1 — Install the backend

The extension is a frontend only. You must have the SIREEN backend running locally. Follow the CLI installation steps above to set up the backend.

Step 2 — Obtain the extension

Method A — Install the pre-built .vsix:

Download sireen-0.1.4.vsix

Then install it:

code --install-extension sireen-0.1.4.vsix

Or via the VS Code UI: Extensions view (Ctrl+Shift+X) → ... menu → Install from VSIX...

SHA-256: d01d33c6de0b3f1db668803dc106e31d4d2bec291e64c06cc32cf7c6e919a6da
Size: 128,229 bytes (125 KB)

Method B — Build from source:

cd goalaif/gaolaif/extension
npm install
npm run compile
# Press F5 in VS Code to open the Extension Development Host

Step 3 — Start the backend

cd goalaif/gaolaif/backend
python -m uvicorn main:app --host 127.0.0.1 --port 7432

Step 4 — Open a Solidity project and analyze

  1. Open any folder containing .sol files (a Foundry project works best).
  2. Open a .sol file in the editor.
  3. Right-click and select Sireen: Analyze Current File.

Step 5 — Review findings and evidence

Results appear in the Sireen sidebar. You will see:

  • Findings list — category, severity estimate, and verdict
  • Evidence packs — PoC source, reproduction steps, Forge output
  • Terminal state — CONFIRMED, DEGRADED, CLEAN_WITH_COVERAGE, etc.

Known limitations
  • Forge is required for CONFIRMED findings. Without it, every finding is needs_review.
  • Only reentrancy, access-control, arithmetic, and DoS vectors are supported.
  • Heuristic mode works offline. LLM-assisted mode requires an internet connection and an OpenRouter key.
  • Business-logic findings can be noisy false positives.
  • Severity labels are heuristic estimates, not authoritative CVSS scores.
