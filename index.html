What SIREEN is, without the jargon

If you have never done security work before, this section is for you. It explains what the tool does in ordinary words. Every technical term is defined the first time it appears.

What it does

A smart contract is a program that moves money on a blockchain. If it has a flaw, someone can drain it. SIREEN helps you check a contract by turning suspicions into tests that actually run — so you can see what is real instead of guessing.

Who it is for

Solidity developers who want to check their own code, and security researchers who want to test a specific idea quickly. It assumes you are comfortable on a command line. It does not assume you are a security expert.

What problem it solves

Reading a contract and thinking "this looks unsafe" is easy. Proving it is slow: you have to write a test, set up a toolchain, and run it. SIREEN does that repetitive part for you, then shows the result honestly — including the failures.

What it is not

It is not a professional audit, and it does not find every bug. It tests a small, clearly defined set of attack types. A clean result means "no attack surface found by today's checks", not "this contract is safe".

Four words you will see on this site
Attack hypothesis
An idea about how a contract might be exploited. Example: "the withdraw function might let someone withdraw twice before the balance updates". It is a guess until something proves it.
PoC (proof of concept)
A small test program written to check one hypothesis. If the test passes, the hypothesis holds under execution. If it fails, the hypothesis did not reproduce — which is also useful information.
Foundry
A free, widely used toolkit for building and testing Solidity contracts. SIREEN uses its forge command to compile and run the tests it generates. Without Foundry installed, SIREEN cannot execute anything.
Evidence
The saved output of a real run: compiler result, test output, gas used, and the exact assertions that passed or failed. Every finding on this site links to evidence you can inspect or reproduce.

The Challenge

Security research is hard.
Proving your suspicions is harder.

Smart contract security researchers face practical challenges every day. SIREEN is designed to help with the parts that a tool can assist — while keeping human judgment at the center.

Complex contracts hide attack paths

A modern DeFi protocol can have thousands of lines of Solidity across dozens of files. Spotting every potential vulnerability manually is exhausting and error-prone.

Hypotheses need proof, not confidence

A static analyzer saying "this looks suspicious" is not enough. You need to know whether the suspicious pattern actually produces exploitable behavior.

Manual PoC writing is repetitive

Writing Foundry tests for every hypothesis takes time. SIREEN generates the boilerplate so you can focus on the interesting cases.

Evidence needs to be reproducible

A finding without reproducible evidence is hard to review, hard to fix, and hard to verify as resolved. Every claim should carry a chain of proof.

How It Works

Five stages. One honest chain of proof.

SIREEN does not claim to automate security auditing. It is a workspace where human researchers guide the process, supported by heuristic analysis and optional AI exploration, with every testable hypothesis put through executable verification.

CONFIRMED

Forge verified at least one finding. Evidence is complete and reproducible.

CLEAN

No findings. Every hypothesis received a real Forge attempt.

DEGRADED

Findings exist but could not be fully verified by execution.

UNVERIFIED

Coverage was insufficient to classify. Needs manual review.

FAILED

Pipeline crashed or every PoC failed compilation.

Stages may be unavailable depending on configuration

Without Foundry installed, Stage 4 (Execute) is skipped and findings remain "needs_review." Without an OpenRouter API key, Stage 2 uses only heuristic patterns. Unsupported vectors (oracle manipulation, flash loans, governance) are honestly skipped.

The reentrancy finding was independently re-verified with a stock Foundry project using the real forge-std — [PASS] testExploit(). // SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

import "forge-std/Test.sol";
import "./VulnerableVault.sol";

contract PoC is Test {
    VulnerableVault public victim;

    function setUp() public {
        victim = new VulnerableVault();
    }

    function testExploit() public {
        victim.deposit{value: 10 ether}();
        Attacker att = new Attacker(address(victim));
        att.depositAndAttack{value: 5 ether}();
        uint256 drained = 10 ether - address(victim).balance;
        assertGe(drained, 2 ether);
        assertGt(address(att).balance, 1 ether);
    }
}

Read this before you rely on a result

SIREEN proves only the specific behavior its generated test exercises. A CONFIRMED finding is real evidence about that path — not proof that a contract is exploitable in the wild. A clean_with_coverage result means the current heuristics found no attack surface; business-logic, economic, and novel vulnerability classes may still exist. Every audit needs human review.

Who SIREEN Is For

Three ways to use the workspace.

SIREEN is designed for people who need to move from suspicion to evidence — not from silence to dashboards.

For Security Researchers

Organize attack hypotheses, generate PoC tests automatically, and keep evidence directly connected to findings.

For Solidity Developers

Investigate potential weaknesses in your own code before they reach production. Understand what a test did and did not prove.

For Protocol Teams

Explore potential attack paths, test specific security assumptions, and review reproducible evidence from your security process.

How SIREEN Is Different

Not another scanner. A verification workspace.

Most security tools stop at detection. SIREEN is built to help you prove or disprove what you suspect — with executable evidence, not confidence scores.

What SIREEN does not do

SIREEN is not a substitute for a professional audit. It does not guarantee security, does not find every vulnerability, and does not replace human expertise. It is a research tool — one that helps you turn hypotheses into executable evidence.
